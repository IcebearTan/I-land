# 下一阶段执行计划：可靠上线与双向信箱

制定：2026-09-30。状态：待实施。依据当前工作区与用户已完成部署的反馈。
执行前读根目录 AGENTS、DESIGN 与 [当前状态](CURRENT_STATE.md)；本文件里的新增字段、接口和事件都是计划约定，尚未实现。

## 1. 目标与范围

验收旅程：小熊寄信 → 她看到未读 → 拆信并看到信纸 → 未读消失 → 她回信 → 小熊收到 → 刷新状态仍在；误删可恢复。

本阶段纳入：部署后的备份/更新可靠性、扫描件写信与回信、受校验附件、创建幂等、作者软删除恢复、收件人已读、岛上未读反馈、旧信导入工具和验收。
本阶段不纳入：已寄出信件编辑、富文本/在线手写、聊天线程、站外通知、复杂新动画、农场、联机、永久附件清理或刷新后草稿恢复。
已寄出的信第一版只读，想补充就再寄一封；这使修改冲突规则保持简单。标题与摘要之外的信件正文以扫描件为主。

## 2. 产品规则（本阶段默认执行）

| 项目 | 规则 |
| --- | --- |
| 发件人/收件人 | 作者取当前登录身份；`bear` 与 `her` 互为唯一收件人，服务端推导，不允许客户端冒用。其他测试账号不能凭默认规则发给任意账号 |
| 新信输入 | 日期 YYYY-MM-DD、标题必填 1–120 字、摘要选填 ≤500 字、扫描件 1–9 页。默认不提供新主题选择器，沿用现有默认样式；旧主题保留 |
| 附件 | 复用 20MB/40M 像素上传限制，JPEG/PNG/WebP；服务端生成 ID、有序且不重复、三档文件存在；新信只能使用当前作者上传的附件 |
| 回信 | 阅读页提供「给对方回信」，进入同一编辑器；作为新信寄出，不增加线程关系 |
| 已读 | 收件人拆开信且首张正文图成功显示后记录；没有信纸的旧信在摘要正文显示后记录。它表示内容已打开，不声称对方读完全部页。封面、请求失败、作者预览均不标已读 |
| 未读 | 按当前收件人计算，不把作者寄出的信算成未读；旧信默认不追踪未读，不在升级时把全部历史信件变成新来信 |
| 删除/恢复 | 仅作者可操作；软删除后双方普通列表不显示，30 天内作者可在「最近删除」恢复；已读不重置。窗口到期不自动物理清理 |
| 草稿 | 仅当前页面内存保留；未保存离开需确认，网络失败和重新登录后可继续。退出账号清除草稿，不能将小熊草稿交给她；刷新或关闭页面不承诺恢复 |
| 内容长度 | 服务端与前端共用相同上限；日期采用已有本地日历日规则，创建/已读时刻采用统一服务端时间并在前端转为当地时间 |

新旧附件引用不得混用产生重复页面；保留旧 `pages_json` 的只读兼容。旧信无需重新编码或重写路径才能继续读。

## 3. 接口与跨层契约

### 3.1 数据建议

沿用 `Letter`，兼容迁移补充 `recipient`、`attachments_json`、`client_id`、
`read_at`、`track_unread`、`deleted_at`、`deleted_by`。默认值让旧行继续可读；
历史作者属于双账号时推导收件人，未知作者不随意改写；历史 `track_unread=false`，新信为 true。
不要伪造旧信已读时间；旧信可继续保持 read_at 为空且不计入未读。

当前只有一位收件人，用 Letter 字段即可，不引入通用多人消息系统。
`(author, client_id)` 用数据库约束保证非空键唯一；旧空键不参与唯一限制。
同键同内容重试返回原信，同键不同内容返回 409；软删除后重试也不重复创建或偷偷恢复。
必须用数据库事务/约束处理同时提交，不能仅靠「先查询是否存在」。

### 3.2 建议接口

| 接口 | 行为与兼容约束 |
| --- | --- |
| `GET /api/letters` | 保持默认返回双方可见、未删除信件；新增 recipient/read/unread 等字段，保留 pages 的既有输出形式 |
| `GET /api/letters/deleted` | 作者的最近删除；静态路径注册在 `/{id}` 前，避免路径被 ID 参数吞掉 |
| `GET /api/letters/unread` | 当前收件人的未读数量；不包含删除或历史不追踪记录；同样注意路由顺序 |
| `GET /api/letters/{id}` | 正常信详情；不得因 GET 自动标已读，删除记录不走普通详情暴露 |
| `POST /api/letters` | 新 UI 提交 date/title/excerpt/attachments/client_id；201 初次、200 同内容重试、409 键冲突；原 author 参数不得决定作者 |
| `POST /api/letters/{id}/read` | 仅收件人调用；幂等、服务端时间、保留首次已读时间；作者调用拒绝；返回最新状态/未读数 |
| `DELETE /api/letters/{id}` | 作者软删除；重复操作不出错，不删附件文件 |
| `POST /api/letters/{id}/restore` | 作者在 30 天内恢复，越期明确拒绝；恢复时保留原状态 |

新公开创建接口不接受任意磁盘路径或外部 URL。`pages` 兼容主要指读取旧行，不承诺继续支持危险的旧创建输入。
实施前检查实际调用者；若有旧调用者仍提交 pages，提供明确的受校验兼容方式或迁移提示，并记录契约变更。
旧信导入使用独立受控工具，不靠公开 API 放开任意路径。

### 3.3 Phaser ↔ React

- 沿用 `OPEN_MAILBOX`、`PANEL_OPENED/CLOSED`；新增全大写事件 `MAILBOX_UNREAD_CHANGED: { count: number }`。
- React 请求 API 后发送真实未读数；Phaser 只显示红旗/爱心/气泡，不处理信件表单或 DOM。
- 登岛、场景重入、面板寄信/已读/删除/恢复后、页面重新可见时同步；页面可见且登录时每 60 秒刷新，不做实时联机。
- 给岛场景增加就绪事件或明确重同步机制，避免首次数据到达早于监听造成未读丢失；退出时清零，清理监听和计时器。
- 网络失败保留上一次已确认值；未知初始状态不能冒充 0，面板提供可重试反馈。
