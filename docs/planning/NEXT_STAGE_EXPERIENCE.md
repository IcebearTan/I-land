# 下一阶段：声音、双人看海与小屋室内

制定：2026-10-01。状态：SOUND-01 已有本地实现与自动检查，听感/真机/线上验收待补；其余包未实施。
依据：当前 `main` / `c2c0097`，以及用户要求的三个优先功能。用户补充：看海可以调整 tick 速度。
先读根 AGENTS、DESIGN 和 [当前状态](CURRENT_STATE.md)。本文件成为当前执行入口；[双向信箱计划](NEXT_STAGE_M2.md)保留为后续任务。

## 1. 阶段目标

让小岛从“走到地方打开内容”增加到“可以留下来相处”：

1. 默认开启轻松的 8bit 昼夜音乐、白天鸟鸣/夜间虫鸣与海浪，设置内分别调节。
2. 从沙滩入口进入独立看海场景，一个人可以先坐着，另一人随后进入同一场景，坐到旁边并简单依靠；两边看到同一轮日出日落，能够调整景色时间倍率。
3. 从小屋门进入真正的室内，在一间温暖的小屋里走动、使用家具，并复用已有信箱和日历。

本阶段实现指定场景的双人共处。主岛继续使用已有异步足迹；室内首版提供本地走动，海边承担首个实时双人闭环。
小屋的完整自由走动联机、家具装修、文字聊天、农场、天气、站外通知和新写信编辑器另行安排。
不能用假的第二个角色或“上次来过”的数据冒充在线同伴。

## 2. 产品规则

### 2.1 声音：柔和旋律与环境声分层

- 2026-10-01 用户调整：默认开启，音量控件收进小岛设置，HUD 不挂声音按钮；手动关闭仍记住个人偏好。浏览器拒绝自动播放时，首次点击/输入同步解锁，登录后无需第二次开启；设置保留“继续播放”。
- 登录页仅播放更轻的音乐。日间《慢慢靠岸》与夜间《星光小岛》同调同节拍，保持循环同步、等功率淡入淡出，避免整点硬切和错拍叠加。
- 三层独立控制：音乐、环境声（白天鸟鸣/夜间虫鸣/海浪）、总静音。个人音量不影响对方。
- 环境声保持完整位深，柔和地融入背景；虫鸣使用真实野外录音，保留连续虫群声，避免短促的提示音节奏。夜色连续变化时鸟鸣退去、虫鸣接上。海边降低音乐、突出海浪，树林增加鸟鸣/虫鸣，室内减弱户外环境声。
- 看海加速只改变景色时间；音乐、海浪播放速度和角色动作保持正常速度。鸟鸣出现的时段可以随景色变化。
- 页面隐藏暂停声音；回来仅恢复本页此前获准播放且用户没有手动关闭的声音，浏览器拒绝时设置保留“继续播放”。下岛停止户外环境声，回到登录页的轻音乐；手动静音不因下岛被偷偷解除。
- 音量/开关通过个人设置 API 保存，不能写 localStorage。调整滑杆在松手/短暂防抖后保存，不随渲染帧写数据库。
- 首版必须有可试听音频及来源记录。只有声音管理器或静音占位文件不算完成。缺资源时单独记录阻塞，不拿未经许可的现成游戏音乐补位。

音频浏览器行为参照 [MDN 自动播放说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。
Phaser 声音管理器属于整个 Game，场景切换不会替开发者停止旧循环，需由一处集中管理。[Phaser 音频文档](https://docs.phaser.io/phaser/concepts/audio)

### 2.2 独立看海：能单独待着，也能一起待着

- 在主岛沙滩放一个可达的看海入口，与漂流瓶入口区分，走近后按 E / 轻点进入。
- 新 `SeasideScene` 是 Phaser 场景。构图包含地平线、天空、海面、沙地与两个相邻座位；保持像素美术，天空/反光柔和过渡。
- 入场沿短路径走到座位并坐下，步行动画由客户端脚本表现，不同步整岛自由移动。
- 两位固定岛民共用一个私人房间。先到者分配一个空位，后到者进入另一空位；身份按用户 ID / bear、her 固定键识别，改名不换人。
- 第一版姿势：坐着、向对方轻靠、起身/结束依靠。依靠只在双方同处且坐着时可用，只改变自己的动作；对方离开或起身后解除依靠。
- 没有同伴时可以照常看海；离开、掉线不消耗资源、不损失内容，也不需要连续签到。
- “先坐着等对方”表示页面处于有效连接状态。手机锁屏或后台超时后释放座位，不能承诺关闭网页后仍真人在线。
- 网络断开时本人继续看海，明确显示“正在重新连接”，停止发送依靠/调速等共享操作。对方状态是待确认的最近状态，不能仍标注实时在线。
- 提供返回小岛；回到入口旁的安全位置。往返位置先保留在当前页面内存；刷新第一版回主岛，旧连接按断开/租约清理，可再次从入口进入。

### 2.3 可调 tick：共享景色时钟

此处 tick 是景色时间推进，不是浏览器刷新率，也不是全局 Phaser timeScale。

- 默认 1×，首次建立房间时从真实时间开始；提供暂停、1×、30×、120×及“回到现实时间”。服务端只接受这些倍率（暂停为 0），拒绝负数/非有限值/任意极大值。120× 时一轮 24 小时约 12 分钟。
- 1× 表示正常流速，不能在加速后自动宣称已回现实时间；“回到现实时间”明确重置锚点并恢复 1×。
- 两个人共享同一组锚点、倍率与时区。谁在房间里都可以调整，对方看到简短提示；并发修改用版本号拒绝旧提交并载入最新设置。
- 景色时区首版固定 `Asia/Shanghai`；不请求定位，不声称精确计算当地天文日出。
- 虚拟时钟只驱动海边的太阳/月亮位置、天空色、海面反光及环境声时段。
- 主岛真实时钟、恋爱天数、纪念日倒数、信件/记忆日期、登录会话过期、心跳和重连间隔不受倍率影响。
- 倍率变化保持景色时刻连续；仅“回到现实时间”允许明确跳转，画面柔和过渡。减少动态模式使用静态/低频变化，时钟状态仍同步。
- 暂停/倍率/锚点经 REST 保存；客户端根据锚点计算每帧景色，不每秒向 SQLite 写 tick。无人时视觉时钟按保存的倍率继续，服务重启后从锚点推导；在线人数重新确认。

### 2.4 小屋室内：一间可以使用的房间

- 主岛小屋门触发 `InteriorScene`；首版一间房，包含门、窗、桌子、沙发、床/地毯及照片墙。布局适配手机，保留整数像素缩放。
- 可以本地走动；家具和墙体有碰撞/遮挡，出口回门外安全点，不能卡在墙里。
- 桌面/信笺打开现有信箱；照片墙打开现有记忆日历；收音机打开个人声音控制。窗外颜色沿真实昼夜变化，室内使用暖灯。
- 桌面也可以显示“写信功能待开发”，不能伪装已有完整写信闭环。
- 打开 React 面板暂停角色输入，合上后恢复；声音设置只操作声音，不顺便开启走位。
- 首版不绘制虚假的在线同伴。将来小屋双人共处复用海边房间协议，若增加自由移动，需要单独设计位置同步。

## 3. 架构建议与明确边界

### 3.1 场景与输入

保留 React + Phaser + FastAPI。独立场景、音频和房间同步都有现有技术栈可用的实现路径，不先引入新渲染框架。

- Phaser 管场景、美术、角色动作、相机、声音；React 管声音控制、看海动作/倍率工具条和现有面板。
- 跨层走 EventBus。拟新增 `TRAVEL_REQUEST`、`SCENE_READY`、`SCENE_CHANGED`、`AUDIO_UNLOCK_REQUEST`、`AUDIO_SETTINGS_CHANGED`、`ROOM_STATE_CHANGED`、`ROOM_ACTION_REQUEST`、`ROOM_CONNECTION_CHANGED`。
- 事件须有明确类型、场景 ID 和必要的请求/版本标识；命名是计划建议，实现时统一契约。
- `GAME_READY` 保留登录/游戏启动语义，新增场景的就绪不能误触 App 的自动登岛。确认目标场景就绪后才消费房间快照，避免 API 返回早于监听而丢掉状态。
- `IslandControls` 从固定主岛摇杆改为根据场景选择：主岛/室内显示漫步控制，海边显示坐下/依靠/返回控制。
- 输入、计时器、碰撞、EventBus/DOM 监听在 shutdown 或 sleep/wake 时有唯一清理/恢复路径；快速往返、失焦、面板关闭不能留下移动状态。
- 场景导航组件复用身份与返回位置；只抽取真正共享的输入/生命周期代码，不大改当前日历。

Phaser 提供 start/shutdown、sleep/wake 等生命周期；具体导航方式在 SCENE-01 中选定并验证。[Phaser 场景文档](https://docs.phaser.io/phaser/concepts/scenes)

### 3.2 音频管理

建议增加一次启动的 `AudioScene` / 集中 AudioDirector，统一使用 Phaser Sound Manager。
它在各场景之间保留音乐实例，按 EventBus 中的场景/区域上下文混音；每个循环最多一份，不在三个场景各建一套播放器。
默认开启遵守浏览器自动播放权限；首次点击/键盘输入在同步链内恢复音频，不能等完登录或保存 API 再尝试解锁。React 设置的继续播放入口也通过 EventBus 同步发送。

新增用户偏好表（如 `UserPreference`，按 user_id）：音乐/环境声开关和 0–1 音量。只返回/修改自己的设置。
建议 `GET/PUT /api/settings/audio`，局部更新音频字段，不覆盖未来其他设置。新表仍放 models.py，兼容迁移放 db.py。
音频资源建议 `frontend/public/audio/`，配 `SOURCES.md` 记录作者、来源、许可、修改、循环点与格式；加载按需，不阻塞登录首屏。

### 3.3 双人房间：REST 操作 + WebSocket 推送

采用房间级同步：REST 提交加入、离开、姿势、时钟；WebSocket 只推送完整快照与连接状态。
这遵守持久化走 API 的约定，避免对既有信件/记忆接口做实时化改造。
FastAPI 可以在 WebSocket 端点中使用 Cookie 和依赖，但仍需本项目的会话与来源检查。[FastAPI 官方文档](https://fastapi.tiangolo.com/advanced/websockets/)

| 能力 | 建议契约 | 核心规则 |
| --- | --- | --- |
| 房间快照 | `GET /api/rooms/seaside` | 仅两位岛民；返回座位/姿势、时间锚点、版本、服务器时间 |
| 进入 | `POST /api/rooms/seaside/join` | 身份取 Cookie；同一页面重试幂等，空位由服务器分配 |
| 姿势 | `PUT /api/rooms/seaside/pose` | 提交目标姿势，不做非幂等 toggle；校验自己的租约与另一位是否在场 |
| 景色时间 | `PUT /api/rooms/seaside/clock` | 校验成员身份与时钟版本，保存连续锚点；重置为明确操作 |
| 心跳/离开 | 独立 heartbeat / leave REST | 仅更新当前租约；迟到的旧 leave 不能清除新连接的座位 |
| 推送 | `/api/rooms/seaside/events` WebSocket | 只读快照；Cookie 会话 + 来源白名单；重连先取完整状态 |

- 只有 bear/her 两位身份可进入；登录名和客户端传来的 author/user_id 不决定身份；测试第三账号/未登录/跨来源连接要拒绝。
- 同一账号同一时刻只控制一个海边角色。新页面明确进入时接管旧租约；旧页面失去控制并提示，不能反复自动抢占。每页生成内存 client_instance_id，用于重试识别。
- 使用租约 ID/代数保护 late close、旧心跳和旧请求；首版建议前台 10 秒心跳、30 秒失联到期，这些是可通过测试校准的协议参数。
- 页面进入后台通知暂离，关闭连接并释放座位；通知失败由到期处理。回来重新验证身份与全量状态；被其他窗口接管的旧页面需要显式重新进入。
- 离开、WS 关闭、租约超时、退出/改密/会话过期清理成员，依靠姿势随之解除；既有 60 秒 visits 心跳不用于占座。
- 房间状态在单进程内串行更新，保证两人同时进入不会占同一座位。快照包含 room_epoch + 单调 revision，客户端丢弃同 epoch 的旧快照，服务重启更换 epoch 并重新确认成员。
- 连接/座位/瞬时姿势放服务器临时内存，掉线与重启不恢复“真人在线”。时钟锚点/倍率与个人偏好存数据库，均只经 REST 改动。
- 两人首版使用一个 Uvicorn worker；当前 Docker 启动命令未指定多 worker。内存房间不支持多进程/多副本，若部署配置不同，先处理共享协调，不能照搬单进程广播示例。
- WSS 使用与网站同源地址；开发代理须支持 WebSocket。真实反代、Cookie、重连与会话失效要上线验证，不因本地 WS 成功就勾线上验收。
- 静态画面不需要持续高频上报角色坐标；不能把短期房间状态每帧写进 WorldState。

### 3.4 时间计算建议

持久化 `RoomClock`（如 room_id、virtual_base_ms、real_anchor_utc_ms、rate、version），新表仍放 models.py。

```text
景色时间 V(t) = virtual_base_ms + (估计服务器 UTC(t) - real_anchor_utc_ms) × rate
改倍率时：先计算旧 V(now)，将它作为新 virtual_base，更新 UTC 锚点与 rate。
```

客户端从服务器时间与网络往返估计偏移，用单调计时推进，而非相信每台设备的本地时间。
重连/载入最新时钟版本时重同步；1×、暂停、跨午夜和快速切倍率都要测试。
房间版本及持久化 clock.version 分工明确：前者排序广播，后者处理数据库并发修改。
