## 本次代码评估对下一阶段的影响

| 当前事实 | 下一阶段处理 |
| --- | --- |
| `LetterIn.pages` 接受字符串列表，现有 Letter 没有附件/收件人/已读/软删除/幂等字段 | 新写信必须建立受校验的附件输入与明确收件人，不直接照搬旧创建接口 |
| `DELETE /api/letters/{id}` 当前永久删除，仅作者可调用 | 改为作者可软删除与恢复；保持对方无权删除的规则 |
| `OPEN_MAILBOX` 的未读数在场景中为固定占位值；没有 UI → 场景的未读更新事件 | 新增持久化已读状态与 EventBus 更新事件；场景就绪/重入时也需同步 |
| 未关联附件候选扫描已识别 Memory 与 Letter.pages 的附件 URL；`linked` 是保守标记 | 新附件字段/软删除落地后扩展回收站引用；继续不物理清理 |
| 现有记忆表单有上传状态等能力，但并非完整通用编辑器 | 复用上传封装、日期控件、焦点工具；仅抽取确有两处复用的照片逻辑，避免重构日历 |
| 恢复工具执行 `PRAGMA integrity_check` 后未判断返回值是否为 `ok` | OPS-01 补齐失败拒绝恢复的检查；验证附件完整性，不能只看目录存在 |
| App 根据登录身份条件挂载面板 | 会话过期重新登录若卸载面板可能丢草稿；M2 需明确页面内草稿保留策略并做端到端验收 |

这里的处理均是待做任务，不表示已修复，也不触碰线上数据库。
