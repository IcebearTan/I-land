## 先看见的问题

实际查看了上一轮 [320px 客厅](../../assets/home-base-01/08-bear-320-right-seat.png)、[设置面板](../../assets/home-base-01/06-bear-muted-settings.png)、[海边桌面](../../assets/home-base-01/19-her-seaside-after-home.png)截图，并与当前 CSS/TSX 对照：

- 设置的厚木框、亮粉主按钮与海边/客厅的细木边、轻工具条不统一；HUD 常规模式另有深紫底，导致同一按钮跨场景换了材质。
- 手机中文多数再次缩小，海边/客厅短操作 9–11px；日历格子、主题名和图标名有 7–10px。正文、元信息、操作之间缺少稳定层级。
- HUD 名字是按钮间的裸文本，长名字缺乏可收缩/换行容器；小屏足迹卡与日历卡都在争用顶部空间。
- 月历、日期弹层、图标、天气和照片操作通过更多列和更小文字容纳；照片移位/删除原来叠在缩略图下沿，触控目标过小。
- 信箱阅读使用固定高度 flex + overflow hidden，长标题/长署名容易挤压纸张；日历编辑器的底部固定操作区在短屏容易覆盖输入内容。

这里引用的图片仅为改动前依据，没有冒充本轮截图。本轮浏览器权限由整合者独占，未新建浏览器或离线浏览器会话。

## 已实施

1. **统一 tokens 和材质。** 新建 `styles/tokens.css`，由 global.css 引入；正文/输入 16px，操作/HUD 14px，元信息 12px，常规标题 20/24px。统一实色奶油底、细木边、4/8px 圆角、浅阴影、青绿主操作、青绿焦点。重写重复的基础样式，把海边样式独立到 seaside.css；保留 `--cream/--ink/--beam` 等旧引用名称。
2. **登录/设置。** 登录信笺短屏滚动整块内容，输入和 placeholder 不缩字；两位账号卡片留换行空间。设置按 16px 正文、14px 表单标签重排；总开关和普通主按钮使用同一青绿色。音频开关可点击外框 44×44，视觉轨道仍是 44×24，滑杆行 44px。
3. **HUD 长名字。** 添加 `.hud-user-name`、`.hud-presence-copy` 包裹；不按 hover 才能看全名字，允许自然换行。小屏将账号栏排成头像/名字/两个 44px 按钮，足迹与日历入口占不同列；海边/客厅 quiet HUD 使用相同材质。没有改变名字来源或身份逻辑。
4. **海边/客厅。** 海边大标题只在入场前 4 秒出现，短竖屏直接保留紧凑场景标签和真实成员状态；两人都坐下才能依靠的说明可直接看见。海边四个操作仍在同一条工具栏，用上下图标文字布局保持 14px。客厅三按钮保持 14px；近电视时，右下双按钮替代重复互动按钮，与左侧摇杆并排，避免更大的提示条挡住电视前的人物。长状态文案在局部可滚动，不强行裁掉正文。
5. **信箱阅读。** 长标题/署名/摘要换行，移除通过省略长摘要节省空间的方式。整面板可纵向滚动，信纸拥有独立且不为零的阅读高度；页码按钮 44px，320px 翻页器分成页码行与按钮行。七夕信封和其他用户内容样式保留。
6. **日历/记忆。** 正文和字段按语义分层。主题/图标按至少 64px 的格子自动换行，样式预设至少 104px；主题色及信笺/票券/花园/星空样式继续由 `--holiday-*` 和既有数据决定。320px 月历面板展开到视口宽度，七列日期按钮保留 44px；小挂历在自己的区域内横向滚动，并有可见说明和键盘焦点入口。表单底部操作回到正常文档流，短屏靠滚动访问。
7. **照片/长文。** 照片下方显示移位、重试、删除按钮；窄屏 2×2 排布，每个目标至少 44px，上传错误不盖住照片或被裁成一行。记忆正文/最近删除描述按 16px 完整换行，作者名字增加容器，大图工具条允许换行。

小屏主岛日历快捷卡现在显示一个明确的“记忆日历”按钮；完整倒数卡在桌面快捷卡及日历内保留。日历的配色、样式选择和保存规则均未变。

## 字号与控件占位契约

所有值是**最终 CSS 屏幕像素**，不是贴图或 Phaser 逻辑像素。下列是源代码布局约定；实际 DOM 尺寸和与新素材的重叠关系仍须整合者实看。

| 层级 | 约定 |
| --- | --- |
| 正文/输入 | 16px，正文约 1.6 行高，字段最小高度 48px |
| 主要按钮/HUD/短提示 | 14px，约 1.4–1.5 行高，有效操作目标至少 44×44px |
| 元信息 | 12px；辅助说明中较长段落使用 14px |
| 标题 | 常用 20/24px；I-land 字标 44px，倒数数字 58px 是明确的展示性例外 |
| 色彩 | 奶油 `#fdf6e9`，浅底文字 `#4a3b55`，深底文字 `#f5eee2`；主操作 `#326860`，浅强调 `#e3eee3`，木边 `#c8ad8b` |
| 间距/边角 | 4/8/12/16/24/32px 间距，控件 4px / 面板 8px 圆角，1px 细边为主 |
| 焦点/动态 | 2px 青绿 focus-visible，3px 外间距；已有字段/按钮 handlers 不变，CSS 继续尊重 reduced-motion |

给场景整合的具体尺寸：

- **≤600px 主岛**：站名/时钟从顶部 12px 开始；账号栏 top 76px，常规高度约 58px；足迹和日历入口 top 144px。右侧日历入口宽 92px，足迹宽 `视口 −124px`。20 字中文名字在账号栏可换行；主岛人物/交互提示的顶部安全区建议先按约 224px 验证，再根据实际内容测量收口。
- **≤600px 客厅/海边 quiet HUD**：账号栏 top 12px，左右各 12px。客厅回岛按钮 top 80px，高度至少 44px；入场短提示 top 136px。Phaser 气泡不可继续套用旧 70–114px 按钮边界，应重新验证顶部区域。
- **客厅行走**：摇杆 88px；底部留约 156px 的普通行走操作区。普通状态文案放在此区上方。近电视时，右下工具条宽 `视口 −124px`（上限 280px），底部 12px，左侧摇杆继续可用，重复的互动按钮隐藏。状态文案可换行，整合者要核对长房间冲突消息。
- **客厅入座**：底部三列工具条宽 `视口 −24px`（上限 360px），按钮高度至少 52px；含通常一至两行状态先按底部 160px 留白验证。极长错误提示可局部滚动，不保证任意长文字都只占这一高度。
- **海边**：小屏四列按钮每项至少 64px 高；含时刻、依靠说明和状态文字先按底部 200px 留白验证。时间设置位于 top 112px，最大高度 `100dvh −336px`；断线时仍能看到成员区的重新加入入口。大标题只显示 4 秒，未重新加入或创建任何房间数据。
- **320px 月历**：面板横向铺满视口，月历左右各 4px，七列日期格不小于 44px；容器独立滚动兜底。日期小挂历固定最小表格宽度 308px，在字段内部滚动，外围页面不要求变宽。新增滚动区域可以 Tab 聚焦，原 Esc/选日期后焦点回到触发按钮的代码保持。
- **照片操作**：桌面四列 44px 操作；≤760px 缩略图双列、操作 2×2。没有通过缩放控件来满足小屏。

这些约定通过文档/文件交接，运行时 React/Phaser 仍只经 EventBus 通信；不要让 React 读取 canvas 或直接控制相机。HOME-02 新增的远端成员、抢座和重连控件如需 DOM 扩展，由整合者在 READY 后统一适配。
