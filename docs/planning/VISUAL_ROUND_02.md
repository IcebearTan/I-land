## 2. 本轮共同目标

把登录、HUD、设置、信箱、日历、海边和客厅变成同一套视觉语言；人物站坐、家具与门的比例统一。验收使用真正的游戏画面，静态图作为设计依据。

### 字号与控件（最终 CSS 像素）

| 角色 | 目标 |
| --- | --- |
| 正文/表单输入 | 16px；长段文字行高约 1.6，输入在手机上不靠缩字号省空间 |
| 按钮/HUD/短操作说明 | 14px 起，根据层级调整；主要操作不使用 8–11px 中文 |
| 次要标签/元数据 | 12–14px；关键含义不可只放在小字或 hover 中 |
| 标题 | 20–24px 为常用层级，场景大标题只作短暂氛围，不长期占据角色空间 |
| 触控 | 有效操作区域至少 44×44 CSS px；小屏先换行/调整布局，不整体缩 UI |
| Phaser 提示 | 约 14–16px 的最终屏幕文字，随相机变焦维持可读尺度；不能把 8px 逻辑字号在不同 zoom 下直接当作同一字号 |

数字是本轮默认设计目标，需要在 320/390px 与桌面实看；不得为了满足一个数字制造遮挡、横向溢出或切掉正文。
正文保持中文系统字体；深底浅字 #f5eee2、浅底深字 #4a3b55。实色奶油底、适度木边、统一间距/圆角/阴影与焦点样式，青绿用于适量强调。
保留现有纪念日主题与用户内容样式；不把主题选择粗暴统一成一种颜色。音量继续在设置里，不新增常驻大面板。

### 人物与家具（游戏逻辑像素）

- 地形仍为 16px tile，站姿与坐姿共用头部大小、脚底锚规范和像素密度，画布不等于碰撞。
- ART-01 的 32×40 人物画布、约 31px 可见站姿、128×65 沙发只是候选，不能直接当已锁定标准。把 24px/约32px可见人物与相应家具在同一真实取景比例下对照，再确定一套完整规格。
- 检查坐垫宽度与躯干/肩宽、人物与门洞高度、电视/窗台高度、杯子与手部、站立与入座时的头部位置。家具应容纳两人自然坐下，避免巨大空座位或小人像摆件。
- 新人物必须提供完整可用方向与步态，以及现有海边/室内需要的坐/站/依靠姿势；侧面可合理镜像。保持白熊长身体圆耳、黑发青绿短袖黑裤，背面不画正面猫脸，不加猫耳或围巾。
- 相机取景、脚底碰撞、遮挡层、交互点和起身安全点一并验证；不通过随意 setScale 放大人物来掩盖素材比例问题。
- 当前室内仍只有本人，双人示意层不能作为在线人物接入。海边继续只画服务器确认的成员。

## 4. 交付与接入顺序

### 阶段 A：并行准备

1. UI 对话先盘点字号/面板差异，完成可运行 DOM 样式修改，输出使用的字号层级、控件占位和未验清单。
2. ART 对话做比例对照、选定整套尺寸并制作完整资源。交付资源键、画布尺寸、可见范围、脚锚/原点、动画顺序、家具占地/坐席/起身点提案、图层顺序和许可证/来源。
3. HOME 对话先实现并测试独立小屋房间、座位与电视同步，同时审计相机/提示/脚锚并准备适配。保留海边行为，不提前硬编码未交付的角色尺寸或使用残缺资产。

UI 与 ART 完成后分别在自己的评估目录写 `READY.json`，包含 `round: "visual-02"`、`status: "ready"`、版本标识、可接入文件清单、接口/尺寸说明、检查结果和未验项。两者写出 READY 后停止修改交付范围，即把后续整合写入权交给 VISUAL 对话。

### 阶段 B：单一整合者

VISUAL 对话根据两份 READY 的版本、文件存在性、接口与尺寸说明确认可接入后继续（不做哈希核验），随后独占本轮相关前端文件及新素材元数据，必要时修正 UI 与素材适配问题。原 UI/ART 对话已停止写入，不能同时继续改同一文件。
如果先完成自己的准备工作而依赖尚未就绪，可以等待并报告实际进度；不得伪造 READY 或宣称整体通过。若任务被中断，留下依赖状态和下一步入口，主对话继续协调。
只由 VISUAL 对话生成最终 `frontend/dist`、操作应用浏览器和临时验收服务。UI/ART 如需按项目要求运行前端构建，应使用各自临时 outDir（例如 `npm run build -- --outDir /tmp/iland-ui-round2-唯一后缀`），不得覆盖共享 dist；ART 同时做离线渲染与图片检查。避免多个构建覆盖产物和多个对话操作同一浏览器。

## 5. 联合验收

- 两种身份分别检查登录头像、主岛走动、海边站/坐/依靠、室内站/坐/走；头部尺寸连续，切场景不会突然变大或变小。
- 根据本轮实际改动选择关键 UI 检查：HUD、设置、声音设置、信箱阅读、日历与记忆编辑、海边控件、客厅操作；正文/表单、提示、按钮有一致层级。
- 320×568、390×844 与桌面，另检查横屏/窗口 resize；记录真实 CSS 视口，不把物理像素当字号。
- 场景边界、门洞、家具绕行、坐席/起身、遮挡、文字安全区、触控区域、长名字、长文字和日夜切换均检查。
- 原有私密内容、静音/减少动态、房间租约/身份与断线行为保持；测试数据全部隔离，不用真实信件/照片/数据库。
- 最终 TypeScript/必要构建与明确列出的相关前端测试通过（不跑全量回归），保存前后对照和实际游戏截图；运行时适配问题由 VISUAL 对话修复。
- 报告“本地模拟视口/实际真机/线上”的不同状态；未做真机或部署继续保留待验。完成 UI/素材不等于完成全站联合验收。

## 6. 本轮新增功能：双人沙发与共享电视

- 使用独立小屋房间，身份来自 Cookie 与稳定账号；不会把海边成员或 visits 当作室内同伴。
- 两位玩家可先后进屋、原子占用不同沙发座位；同座竞争得到清楚反馈。未确认入座的远端角色不画成坐在沙发上。
- 只同步沙发座位/坐姿和电视状态，不实现整间房自由走动联机。对方起身只表示暂时不在沙发上，不能据此声称离开小屋。
- 共同开关电视、换台和节目进度；REST 保存电视开关/频道/进度锚点并做并发版本检查，快照推送给另一位。进屋读取共享状态，不再由某一客户端强制重置电视。
- 个人音量/静音独立；屋内日夜跟现实，电视节目不随海边景色倍率加速。
- 保留租约、epoch/revision、重连、同账号接管、后台离开、迟到请求保护等现有原则，跨房间先释放自己的旧租约。服务重启只恢复电视设置，不恢复假在线成员。
- 验收必须包含独立 Cookie 的双身份会话、先后入座、抢同座、起身/离开、双方换台与冲突、重连及海边回归；不能以两个人物素材截图代替真实共处。

这轮交付包含真实双人客厅与视觉一致性；合作暖饮、背包、装修、自由同行继续按后续内容排期。
