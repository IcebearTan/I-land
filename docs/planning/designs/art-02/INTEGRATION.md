# ART-02 资源接入契约

版本 `art-v2.1.0`，日期 2026-11-07。唯一机器可读入口：`frontend/public/art-v2/manifest.json`。所有坐标为游戏逻辑像素，PNG 为原生整数像素；禁止再单独 setScale 放大人物来适应旧家具。

## 角色

| 项 | 约定 |
| --- | --- |
| 画布 / 可见站高 | 所有 56 帧均 32×32；两位四方向待机可见高度均 24 |
| 画布内脚锚 / origin | `(16,29)` / `(0.5,0.90625)`，所有场景与姿势一致 |
| 脚底碰撞建议 | 8×4；相对脚锚 `(-4,-4)`，对应帧 offset `(12,25)`；最终由整合者实测 |
| 方向名 | `down/up/right/left`；原 `front/back/side` 对应 `down/up/right` |
| 待机 | `{account}-idle-{direction}` |
| 行走 | `{account}-walk-{direction}-{0..3}`，7fps 循环；减少动态用对应 idle |
| 客厅 / 海边坐姿 | `{account}-sit-up`；不用旧 22×23 角色 |
| 海边站立 / 入场 | `{account}-idle-up` / `{account}-walk-up`；不用旧 22×32 站姿 |
| 依靠 | `{account}-lean-left-{0,1}` / `lean-right-{0,1}`，5fps 两帧、末帧保持；减少动态直接末帧 |
| 头像 / 登录 | `{account}-idle-down`；可从纯数据重画头像，但 viewBox 必须同步 32×32，不能保留旧 16×16 |

`left/right` 在新帧键里是**身体实际朝哪个方向靠**，不是座位名称。左席 0 向右靠，右席 1 向左靠；这与旧 `seaside-*-leaning-left` 的“左座位”命名含义相反，不能机械替换字串。

海边建议普通座位相对中心 `[-12,+12]`，双方依靠 `[-9,+9]`；单方依靠仅该人的目标改为对应 `[-6,+6]`，另一人仍留普通位置。站立脚点比坐姿脚点低 14px。人物头形保持，依靠靠躯干和头部平移完成。真正在靠谁仍由房间确认姿势与成员控制。

`characters-pixels.json` 提供同样 56 帧的纯字符网格与色板，可继续走现有 `makeTexture`/React 头像数据路径。已验证重建与 PNG 逐字节一致；两种方式选一套作为真源，禁止让主岛保留旧 16px、海边用旧 32px、客厅用新 24px。

## 图集与独立资源

- `characters-atlas.png/json`：1024×80，56 帧，Phaser 常规 JSON hash 格式。
- `home-atlas.png/json`：1024×368，42 帧。
- 两个 atlas 都不 trim、不旋转；2px 边距、1px 边缘 extrusion，保留透明隔离像素。
- 各帧单件 PNG 同时交付。`manifest.characters/home` 给出 URL、atlas key、frame key、尺寸、可见 bbox 与 origin。
- `characters-pixels.json` 是数据入口，不是后端状态；不会涉及 localStorage 或持久化。

## 客厅分层与锚点

日夜家具键后缀为 `-day/-night`；`manifest.homeLayout` 包含样板位置、层序和对象。房间仍是 320×240，出入口 `(272,218)` 与前墙 40px 开口保持原入口语义。

| 壁炉 | `(34,31)` / 76×86 | 火焰 `(59,74)` / 28×28 四帧；占地 `(42,103,60,14)`，互动 `(73,126)` |
| 电视机壳/柜 | `(135,55)` / 60×64 | 屏幕 `(148,70)` / 27×20；占地 `(142,99,47,19)`，互动 `(165,130)` |

电视屏幕、窗外在带真透明洞的机壳/窗框之后画。现有三个电视频道需要按 **27×20 原生绘制区域** 适配，不把旧 48×28 画面任意拉伸；共享开关、频道与节目锚点仍由 HOME-02 状态决定，样例 `tv-screen` 只是初始/静态参考帧。火焰以首帧作为减少动态版本，常规 5fps；不改音频速度或引入燃料惩罚。

日夜静态资产已经带环境受光，整屋切换时不要再叠同一层夜色 tint；人物本身是中性材质，可用同一场景光照规则。精确颜色映射在 `build.py::lit`；接入时可交叉淡化两版静态层，不能让人物/帧尺寸在日夜间改变。

墙/地板先画；地毯/接地阴影不挡人；实体家具与走动人物按脚底 Y 排序；坐着的人物在沙发底座后、近侧靠背前。不要把整张近侧靠背永久画在所有走动人物上方。所有 footprint 和坐席是**提案**，未作为运行时碰撞结论。

## 主岛门与小屏

新门单件为 30×40，净门洞 22×32；原小屋门块约 20×28、内门板约 14×24。选定 24px 人物仍需要扩大净开口。可在现有 120×112 cottage 纹理中以约 `(44,61)` 放置此门，净门洞对应 `(48,66)`，中心与原门对齐；需要按现有屋顶、门廊、台阶绘制顺序核对，不能盲目覆盖建筑或移动入口坐标。灯塔等其他入口也须在联合验收检查。

手机用固定 2× 像素；320/390px 显示的人物站高约 48 CSS px。相机需要跟随/平移，以看到壁炉、窗与出口；不要把 320px 全屋缩成 1×。Phaser 提示按最终 14–16 CSS px 计算，HUD/面板由 UI-01 字号系统负责，场景画布不能承载像素中文正文。

## 整合后必验

两位分别经过登录头像→主岛四向移动→海边站/坐/单靠/双靠→客厅走/坐/起身，头部尺寸连续。检查动画脚锚、双人换座/同座竞争、角色遮挡、边几与沙发绕行、门洞、返回点、resize、320×568/390×844/桌面、减少动态与断线成员清理。构建和静态素材检查已完成，真实游戏、联机、碰撞及真机证据仍由整合者补齐。
