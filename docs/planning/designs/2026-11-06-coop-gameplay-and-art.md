# I-land 下一阶段候选方案：一起生活、一起玩、留下故事

日期：2026-11-06。
依据：用户希望强化双人互动、游戏性和记录属性，并反馈后续场景美术完成度下降，希望向《星露谷物语》的像素质感靠拢。
状态：用户已确认将全部讨论方向纳入项目；具体内容排期与任务见 [NEXT_STAGE_COOP](../NEXT_STAGE_COOP.md)，不设置实现时间。本文保留玩法设计与取舍，新增玩法尚未实施，发布继续沿用现有验收要求。

## 1. 建议的长期方向

**两个人一起生活的小岛游戏，玩过的事情会成为这个家的历史。**

一次体验形成这样的循环：

相约来到一个地方 → 分工完成一件小事 → 获得一个具体作品或发现 → 放进共同的家 → 想起时再看。

例如：一起做热可可，把两只杯子放在壁炉旁，拍下一张合照；以后点击那张照片，可以看见当时的场景、日期和两人各自写下的一句话。

三个核心需要同时成立：

- **双人互动**：对方做什么，会改变我的选择或眼前的画面；存在可交换的分工、回应和共同决定。
- **游戏性**：有可观察的规则、选择和反馈；可以试另一种做法，逐渐发现新组合。
- **记录**：玩家主动保留值得记住的瞬间，日历、信箱、陈列物共同承接；一次游玩结束后，岛上多了一点属于两人的东西。

## 3. 美术升级：先建立一块真正精致的样板

### 3.1 当前观察

观察依据为主岛/海边已存截图、客厅设计草图和当前绘制代码；草图不当作当前游戏的完整实机截图。

- 早期主岛的树冠、建筑屋顶、岸线和落地阴影已经有一定层次，可以保留其色彩气质与空间关系。
- 海边保留了安静的留白，但远近水纹、岸线、前景小物和人物细节还能精修。
- 客厅的功能分区清楚，家具与地板仍较依赖规则矩形和重复线条；石块、布面、木材之间的质感差异不足。
- 主岛 16×16 人物与独立场景专门坐姿采用不同制作规格；需要统一头身、像素密度和家具比例。
- 正式 Tiled 地图/图集管线仍未完成。现有程序绘制适合占位和动态效果，精修静态家具需要更稳定的逐件资产维护方式。

### 3.2 想接近的视觉特征

以《星露谷物语》的生活感、材质和俯视空间语言为参考，保留 I-land 的白熊、青绿衣服、暖光和海岛色彩。

| 维度 | 升级方向 | 在本项目里的具体表现 |
| --- | --- | --- |
| 体积 | 家具有明确顶面、正面、侧面和接地阴影 | 沙发扶手有厚度；坐垫有轻微凹陷；壁炉炉膛有纵深 |
| 材质 | 细节沿物体结构布置，集中在需要辨认的部位 | 木板少量节疤/错缝；布料折痕/缝线；石块局部破边；陶杯高光 |
| 色彩 | 同一材质有克制的明暗层级，阴影带少量冷色 | 暖木与青绿形成呼应，夜间窗外偏冷、炉边偏暖 |
| 比例 | 人物、门、座位和可拿取物共用比例表 | 杯子能被拿在手里；坐姿保持站姿的头部大小；门不会比人物还矮 |
| 构图 | 用前中后景和少量生活痕迹组织空间 | 地毯压住沙发、墙边有踢脚线、毛毯自然垂落；走动区保持清楚 |
| 动画 | 先画准关键姿势，再增加少量过渡 | 坐下时身体落入坐垫；递杯时手臂有路径；火焰稳定亮芯上方摆动 |
| 界面 | 场景负责氛围，操作提示短而清楚 | 中文继续系统字体，提示避开炉火、人物和电视；常态减少大块说明牌 |

细节不平均铺满全屏。视觉重点放在人物、主要家具和互动点；海天仍保持开阔，避免把海边堆成杂物陈列台。

### 3.3 候选统一规格

- 地形保留 16px tile 和整数缩放。
- 先试作一组约 32px 高的站姿人物：黑发角色可用较窄画布，白熊保留宽度和长身体。与现有 16px 版在相同视口对照后，再锁定全场景规格。
- 坐姿和站姿共用头部尺寸、五官与衣服细节；坐下通过姿势缩短身体，不整体放大角色。
- 角色脚底碰撞与画布尺寸分开，精修美术不自动扩大碰撞盒。
- 色板沿用 DESIGN.md 的核心色；新增木材、布料、石材等派生色先记入材质表，再统一用于资产。
- 首批动作以四方向待机/走路、背面坐姿、拿杯为主；拥抱、牵手等需要独立动作设计，再分批制作。
- 小屏至少检查 320/390px 视口中的人物辨认、44px 操作目标与文字对比；模拟视口和真机分别记录。
- 减少动态模式保留静态光影、即时姿势与全部玩法反馈。

### 3.4 首轮美术范围

**推荐先精修“壁炉—沙发—窗户”这一角。** 已有场景和交互可复用，也最能检验木、石、布、火光、人物是否协调。

交付物：

1. 同一构图的白天/夜晚对照图。
2. 白熊和黑发角色的站姿、坐姿比例对照，不把示意双人当作已实现联机。
3. 壁炉、沙发、地毯、窗、电视五件主要资产及少量装饰的原始分辨率预览。
4. 家具占地、遮挡层、互动锚点与图集资源；可进入实际游戏检查。
5. 一张简短风格表，记录像素尺度、主色、阴影方向、材质样例和禁止混用的规格。

验收：人物坐进去自然；白天、夜晚都能辨认材质；手机没有靠缩成微型场景掩盖细节；灯光和提示不遮挡主要动作。

资产路线建议采用“原创主要家具与角色，逐步建立图集”的方式。若以后选用统一素材包，先核对许可并重着色。AI 概念图可用于比较构图和气氛，落入游戏的像素尺寸、透明边缘、帧对齐和碰撞仍需逐项整理。
静态场景逐步迁入 Tiled + 图集；天空、火光、水面等动态效果继续由代码控制。不把整张概念图直接作为一张不可分层的可玩房间。

### A. 一起待着与小动作

**体验**：她先到家里坐下，你走过去，递给她一杯暖饮；她选择接过，两个人碰一下杯。之后可以继续看电视，或者一起去海边。

首版范围：

- HOME-02：真实双人沙发、座位占用、共同电视频道和播放进度。
- 三个可见动作：挥手、递杯、碰杯。双人动作需要另一位回应，可以忽略或取消。
- 简单邀约：“来家里坐坐”“一起去看海”。站内显示，点击后由本人决定前往。
- 一次完成动作后可选择拍照，普通动作不自动填满日历。

接续版本：同一小场景内自由走动、跟随散步、牵手、撑伞。先解决位置同步、走位校验和动画衔接，再扩展到主岛。

离线时：邀请变成下次登录可见的便笺；不能显示对方已经接受、正在坐着或正在跟随。
完成标志：两浏览器看到同一次递杯/接杯，离开或断线不会留下假同伴或卡住的动作。

### B. 双人暖饮与小厨房——推荐第一个完整合作游戏

**第一份作品：两杯热可可。** 加一个小型料理台即可，先借用客厅空间，不要求先建完整厨房。

一局流程：

1. 一人发起“做点热的”，另一人加入；两人各自选杯子和一种配料。
2. 一人调节炉子的火候，另一人搅拌。温度在宽松适宜区间时，搅拌使制作进度前进；搅拌会影响温度，需要彼此配合。
3. 可以交换分工，讨论想做偏浓还是偏奶的口味。
4. 一起分杯，选择棉花糖/可可粉等装饰，给这次配方起名。
5. 把杯子端到沙发边，碰杯、拍照，或直接开始下一件事。

游戏性来自控温与搅拌互相影响、配方选择和分工交换。首次提供宽松提示；熟悉后可尝试不同组合。
越过温区只暂停制作进度，不烧毁原料、不扣分；暂停和断线不会报废作品。一人也能顺序完成两个工位。

最小版本：一个活动房间、一种基础饮品、三种配料、两种杯型、三种成品外观。基础食材直接供应，首次不绑定种田、货币和采购系统。
阶段完成时经 API 保存；重连从最近安全步骤继续。每局结束最多产生一份共享成果，重复请求不会复制成品。
个人杯子可各自领走；共同配方和可选纪念卡以同一局活动关联。

后续扩展：烤饼干、饭团、野餐盒。新配方应带来新选择或分工，避免只换图标、重复同一进度条。

完成标志：两个人有不同但互相影响的操作；交换角色仍可完成；成品能出现在客厅，并能查看制作日期、参与者和所选配料。

### C. 潮汐洞穴与双人寻宝

**体验**：你拿着旧地图，她提着灯。地图标着路线，灯能照出墙上的符号；两个人对照线索，打开海边的一只小箱子。

首个 10–15 分钟小章节：

- 一个地图纸片发现点、一段浅滩、一间洞穴；不先做随机大地图。
- 关卡一：两人各看见半张线索，交流后选择正确的三个符号。
- 关卡二：一人控制水闸，另一人观察水位并摆放浮木；操作可以交换，失误可直接重试。
- 关卡三：共同选择宝箱里的纪念物样式，得到一个可陈列的小摆件。

宝物可以是贝壳风铃、玻璃浮球、迷你船，不以装备数值推动反复刷取。
关卡完成后留下日期、双方选择和一枚地图印章。重复进入可以换路线或探索遗漏，不重复强制观看所有说明。

单人模式允许依次使用两种工具，解谜进度保存；二人模式的价值是交流与协作。潮汐只改变呈现和路线，玩家错过现实时间仍可重玩。
风险：内容制作量较大。先验证一个双人谜题是否有趣，再画完整洞穴和后续章节。

### D. 花园、育种与小礼物

**体验**：你种下一排花，她后来调整其中两种的相邻位置；下次开花时得到一个新颜色。采一朵插到床边的花瓶里，附一句“今天这个颜色很像你的衣服”。

首版：四块花圃、三种花、少量固定可发现的邻接配方、一个花瓶。
种植、调整相邻搭配、等待开放、选择保留或赠送形成循环。发现新组合时给出线索，允许有意识地试验。
成长按服务端现实时间推进；成熟后保留，离线不枯萎。浇水提供短暂视觉回应，不设置必须每天补齐的义务。

双人价值：一起商量搭配、异步继续对方留下的花坛、送出有来历的礼物。
记录价值：第一朵特别的花、某次赠送及自选附言；普通浇水不逐次写进记忆日历。

先保证“种出一朵花 → 送到对方手里 → 放入家中”完整，再增加果蔬、更多育种、交易和资源种类。

### E. 拍立得、两个视角与时光胶囊

**体验**：在海边点“留住这一刻”，两人选择姿势；倒计时后获得一张不带操作栏的像素合照。你写“今天风很好”，她晚些时候补上“其实我是来看你的”。

首版：

- 拍摄预览、重拍/保存，一种相纸样式，海边一个拍摄点。
- Phaser 生成场景图，经 EventBus 提交给 React；由现有附件 API 保存，再进入记忆卡。React 不直接操作 canvas。
- 参与者和共同动作来自真实房间状态；拍摄时连接变化会提示重拍/改为单人，不能拼出假在线合照。
- 每位岛民有自己的落款段落，允许稍后补写；默认不能用自己的输入覆盖对方段落。
- 实际日期与游戏景色时间分别标注：加速看到的日出不伪装成现实清晨。
- 游戏照片/活动与真实生活照片有清楚来源标识，但都能在现有日历检索；不另建互不相通的第二本日历。

接续版本：一段语音、信件回信、设定开启日期的时光胶囊、把记忆转为墙上照片。
时光胶囊通过服务端时间判断开放；错过当天仍可开启。语音和上传影片会增加存储、播放与输入适配，放在后续。

记录采取“玩法有成果后顺手保存”的方式。自动生成可放弃的事实草稿，不替真人编造对话、感受或评价关系。
关闭保存预览不留下半条记忆，双人同时保存同一张合照不产生两份重复数据。

### F. 共建家园与有来历的收藏

**体验**：第一次探险获得的风铃挂在门口；一起做的杯子放在壁炉台上；那次看日出的合照挂在沙发后面。点击物品就能回到它的来历。

首版先给六个固定陈列位置：壁炉台两处、墙上两处、窗边一处、门口一处。每处提供几种合适物品。
两人都能提议和摆放，冲突时采用版本检查；替换物品会放回收藏，不销毁记忆或道具。房屋设置支持恢复上次布局。

收藏来源优先是一起做过的活动、花园成果和明确送出的礼物。建筑/装饰解锁通过不同类型的发现与创作，避免重复刷次数。
接续版本再做家具拖放、旋转、空间布局和庭院；这时需要验证可走路线与坐席/出口可达。

“家具承载记忆”在这里有明确含义：查看一件纪念物的来源。沙发仍负责坐下，壁炉仍负责取暖，常用动作保持自然。

### G. 观星、雨夜和小型共同事件

首个事件推荐“把星星连成一个名字”：两人在海边各选几个光点，轮流连线，保存一张自定义星图。
它更偏共同创作和仪式感；若需要解谜，可加入两人各看到部分图案的模式。

其他候选：雨天共撑一把伞；躲进小屋听雨；放一盏水灯；捡到一只可写回信的漂流瓶；按已有纪念日布置一张特别桌布。
事件可预约或手动重访，时长由玩家控制。天气和节日不惩罚错过的人；不以连续登录天数维持奖励。
首版只选一个事件做完整，不同时开天气系统、节庆系统和大量随机事件。

## 5. 三条可选择的成长路线

### 路线一：一起生活的小屋（推荐）

美术样板 → 双人沙发/共同电视 → 热可可合作 → 拍照与记忆 → 六处陈列位 → 更多小食与小动作。

适合：最想要温暖日常、轻松配合、平时也能经常打开。
优势：壁炉、沙发、电视和声音都已有基础；一个小场景可以同时承接互动、玩法和记录。
主要投入：人物动作、家具精修、小范围同步与合作状态机。

### 路线二：一起探索的海岛

美术样板 → 双人活动房间 → 一个信息互补谜题 → 潮汐洞穴短篇 → 宝物陈列与探险手账 → 主岛同行。

适合：最想要“约好一起玩一局”的感觉，对发现、解谜和探索更兴奋。
优势：共同目标明确，新内容可按小章节发布。
主要投入：关卡设计、地图与机关美术、联机状态；每个章节都需要足够好的内容。

### 路线三：慢慢长大的记忆小岛

美术样板 → 海边合照 → 花园与送花 → 共同手账/回信 → 时光胶囊 → 记忆陈列与庭院布置。

适合：两人上线时间经常不同，希望一年后这座岛充满共同经历。
优势：沿用现有记录功能，异步也能有回应。
主要投入：物品/记忆关系、状态保存、送达与回信体验；纯合作游戏的提升较慢。

推荐组合是路线一的首个合作活动，加路线三的记录出口。后续再从路线二挑一个短篇探险。

## 6. 推荐实施顺序与验收

按实际交付组织，暂不给固定天数。每个包都可单独检查与提交。

| 顺序 | 可交付结果 | 验收要看什么 |
| --- | --- | --- |
| 0 现有客厅收尾 | 补浏览器体验和实现记录，整理未提交改动 | 门口互动、进出、坐姿/电视、设置暂停、手机构图；不把历史测试数当新验收 |
| 1 ART-01 美术样板 | 一角精修客厅、人物比例表、日夜对照、首批图集 | 同一像素尺度、材质/体积可辨、手机可读，进入游戏后保持质感 |
| 2 HOME-02 一起坐下 | 独立小屋房间、双人座位、电视共享 | 双会话先后加入、同时换台、断线、离开；个人音量独立 |
| 3 PLAY-01 第一杯热可可 | 一局可完整合作、交换分工并获得两杯作品 | 两人的动作确实互相影响；暂停/重连不丢阶段；结果只发一次 |
| 4 MEMORY-01 留住这一次 | 海边合照 + 合作成果纪念卡，进入原有记忆日历 | 可重拍/放弃/续写、真实参与者、来源清楚、重复保存不重复入库 |
| 5 HOME-03 家里留下作品 | 六处陈列位、杯子/照片/花瓶来源可回看 | 另一人刷新可见；同时修改不覆盖；替换可撤回 |
| 6 选择一个新方向 | 花园送花，或一个探险短篇 | 活动有完整开始/过程/成果/记录，完成后再扩展内容量 |

美术与玩法可分两次小步交付：先用已有图形验证合作规则，再精修动作与反馈；进入主线时必须达到 ART-01 的统一标准。
真实数据保护、备份/恢复、旧信与记忆回归、线上 HTTPS/WSS 继续按 EXP-QA 验证，发布证据与本地结果分开。

## 7. 工程上需要补什么

### 两个阶段的同步

第一阶段沿用小范围活动房间：沙发、料理台、拍照点各有真实成员与共同活动状态。可以先在固定工位做合作游戏，不必把整座岛的所有物体一起同步。
第二阶段让同一场景看见对方走动：位置/朝向/动作、插值、地图碰撞与速度校验、跨场景交接。随后再做牵手、跟随和主岛同行。
现有海边接口与运行时仍写死 seaside；可复用租约、重连和顺序校验的经验，但添加小屋不是简单换一个房间名。

### 持久化与瞬时动作

- 走路、表情、当前在线成员属于实时状态；重启不能恢复虚假在线。
- 作品、库存、活动安全步骤、配方、布局和记忆通过 REST 落库，再用房间快照通知另一位。
- 领杯子、采花、送礼、完成活动需幂等与事务，避免重试和同时操作复制/吞掉物品。
- 新玩法使用服务器校验的动作命令，不让客户端直接提交“我现在有多少奖励”。
- 现有 `/api/world` 是通用 JSON 读改写，不能直接把它当已完成的库存与并发保护系统。新对象按需增表，加入事务/原子版本检查。
- 按稳定 user_id / bear、her 关联，改显示名字不换人或丢作品；个人音量、减少动态不写成共享设置。
- React 与 Phaser 继续只经 EventBus 传动作与快照；不从 UI 读取 canvas 内部状态，不把游戏存档放 localStorage。

### 作品与记忆的数据关系（概念，不是已存在的表）

活动局保存活动类型、真实参与者、阶段、选择和结束结果；纪念物关联其来源活动/赠送；记忆卡可关联同一个来源，再加双方自己的文字。
这样一张合照、两只杯子和一段日历记忆可以讲同一个故事，同时避免为每个玩法另建一套孤立记录。
第一局热可可只实现它需要的最少字段，不提前搭一个复杂通用任务引擎。

## 9. 暂缓的扩张与取舍

- 先用合作活动和作品收藏带来成长感；货币、商店、体力、饥饿、经验等级留到有明确用途时再评估。
- 不把登录连续天数、回应速度或谁做得更多转换成关系评分；暂停游玩不会损坏共同成果。
- 更多房间要承接一种新活动。厨房对应合作制作，温室对应培育，工作间对应共同创作。
- 地图、家具和配方数量跟随可玩闭环逐批增加；优先让第一局确实有意思。
- 固定像素节目之外的真实视频共同播放另立专题，涉及播放源、平台限制和进度同步；不混进本轮温暖客厅收尾。
- 一键全岛换美术风险较大；先锁定样板，再按客厅、人物、主岛、海边迁移，并回归碰撞、遮挡与缩放。

## 10. 选择时最值得回答的三个问题

1. 更想约对方来“待一会儿”，还是“玩一小局”，还是“看我给你留下的东西”？
2. 最想先留下什么：一张合照、两杯自己做的饮品、一束花，还是一件一起找到的宝物？
3. 美术样板最想先看到哪里：壁炉旁、海边前景，还是两位角色的新站姿/坐姿？

无需一次选完整路线。选一个场景、一件共同活动、一种纪念物，就能形成下一阶段有明确终点的开发包。
