# I-land 功能盘点与下一阶段建议

盘点日期：2026-09-30。依据当前代码、README、DESIGN 与本次复验结果。
本文是开发建议；未完成任务不会因为列入计划而标记完成。

| 操控与交互 | WASD/方向键、点击地面、手机虚拟摇杆；靠近提示、互动按钮；开面板暂停角色输入；减少动态偏好处理 | 手机真机仍需验收，点击移动不含复杂寻路 |
| 异步共岛 | 登录与定时心跳；展示对方最近来过的时间 | 没有实时同屏，也未形成完整的行动痕迹系统 |
| 信箱 | 信件列表、封面、火漆拆信、图片信纸翻页；加载/失败/空状态；后端列表、详情、创建、删除接口，作者由登录身份确定 | 尚无写信/回信界面、扫描件上传闭环、旧信迁移或未读状态；M2 未完成 |

| 每日记忆 | 同日多条；照片、描述、标题、心情、天气、地点；多图预览/排序/上传进度/重试；月历缩略图、日视图和大图；共同编辑、版本冲突提示、创建幂等、软删除与 30 天恢复；页面重新可见时刷新 | 本地实现与检查通过；手机完整旅程、弱网和会话过期后的输入恢复还需专项验收 |
| 图片与数据保护 | JPEG/PNG/WebP 上传、三档 WebP、方向纠正、EXIF 去敏；登录后访问照片与旧信纸；附件引用校验；旧库兼容迁移；SQLite 与附件整套备份、独立目录恢复演练 | HEIC 暂不支持；未关联附件仅列出候选，不自动删除；真实 TLS 和容器部署仍待实测 |

里程碑判断：M0 已完成；M1 可玩但缺正式资产；M2 完成阅读部分；
M3 核心功能已实现，但真机与部署验收未收口；M4–M6 尚未完成。

## 3. 建议下一阶段：先验收，再补齐写信回信

目标：让小岛先成为两个人可以放心持续使用的空间，并完成「我寄一封信 → 她读到 → 她回信 → 我读到」的核心旅程。
优先复用现有上传、身份、面板与日历能力，不同时扩展农场、联机和多种新场景。

### P0：收口当前版本的使用与部署验收

- [ ] 用 iOS Safari 和 Android Chrome 分别完成登录、走位、打开日历、多图记忆保存、另一账号查看、修改、删除恢复和改密。
- [ ] 检查键盘弹出、长文滚动、触摸操作、焦点、面板关闭确认及减少动态偏好。
- [ ] 人为制造上传失败、保存超时、重复点击、会话过期与双方编辑冲突；验证输入保留、可重试和不重复生成记录。会话过期后的重新登录恢复作为重点检查项。
- [ ] 验证 Docker 新数据卷首启、已有数据升级、重启持久化，以及真实 HTTPS 下的 Secure Cookie。
- [ ] 在独立目录复验备份恢复，并配置实际部署的定时备份与异地副本。

验收产物：记录设备/浏览器、操作路径、通过与失败项；阻断登录、照片保存或恢复的问题先修复。
Docker 和 HTTPS 需要实际运行环境，缺少环境时保留未验证状态。

### P1：补齐 M2 写信与回信

- [ ] 信箱增加「写一封信」入口：日期、标题、摘要、扫描件上传、预览和页面排序；两位岛民均可寄信。
- [ ] 新信通过服务端附件标识关联，复用上传三档图与登录访问保护；旧 `pages_json` 保持兼容，不能直接把任意客户端路径当作新附件。
- [ ] 保存时校验日期、文本、附件存在性和作者身份；防止重复提交产生重复信件。
- [ ] 明确删除规则；建议新信采用软删除与恢复，避免直接套用现有永久删除接口到新的 UI。
- [ ] 为每个收件人记录已读状态；读完后更新信箱红旗/爱心提示，刷新与再次登录仍保持状态。
- [ ] 建立旧 IcebearMailbox 导入工具：先预览数量、排序和缺失图片，备份后导入；重复执行不重复入库，核对旧信页数与图片完整。
- [ ] 完成两账号与手机端验收：寄信 → 对方看到未读 → 拆信逐页读 → 标记已读 → 回信 → 刷新后内容与状态仍在。

依赖：现有图片上传与身份系统；如旧信源不在仓库，需要取得源文件后才能验收迁移。
读信状态属于真实持久化数据，应走 API；未读反馈通过 EventBus 传给 Phaser。

## 4. 后续顺序

| 顺序 | 工作包 | 原因与最小验收 |
| --- | --- | --- |
| 1 | P0 当前版本验收 | 先确认手机记录与数据保护可靠，避免继续叠加尚未验收的能力 |
| 2 | P1 写信/回信/未读/旧信迁移 | 补齐已有核心模块，复用上传管线；双向通信闭环通过 |
| 3 | M4 漂流瓶 | 日常短留言门槛更低；发送、接收、已读、收藏、海滩表现闭环，珍藏架场景可另拆 |
| 4 | M1 正式资产收口 | 根据完成后的交互点做 Tiled 地图、图集和许可/调色板记录，保留碰撞与触摸体验；在扩建农场前完成 |
| 5 | M5 种花送花 | 先做少量地块与一两种花；明确共享时区与每天浇水边界，漏登录只暂停；种 → 浇 → 收 → 送 → 对方收到闭环 |
| 6 | M6 氛围与回看增强 | 再考虑天气、音乐、去年今日和成就；依据实际使用反馈选择，不一起铺开 |

如当前手机首屏或画面是主要阻碍，可把 M1 正式资产与加载优化提前到 M2 之后；
优先级由真机验收决定。下一阶段建议聚焦 P0 + P1，漂流瓶和农场作为后续阶段独立验收。

## 5. 持续遵守的边界

Phaser 与 React 仅通过 EventBus 通信，所有持久化走 API；正式地图/图集遵守
16px 与 DESIGN 调色板。无惩罚原则、中文正文可读性、对比度和减少动态偏好继续适用。
`backend/iland.db` 与 `backend/uploads/` 是真实内容，继续忽略、不删除、不提交。
